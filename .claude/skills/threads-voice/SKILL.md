# threads-voice

## 로드 순서 (건너뛰지 말 것 — 단, 아래 것만. 토큰 절약)

1. `references/voice-profile.md` — v3 실측 규칙 10개 (이력은 voice-history.md, 규칙 갱신 때만)
2. `references/few-shots.md` — **1부 = 내 계정 실측 WIN 6건이 1순위 기준**, 2부 = 코퍼스 보조 3건
   (매트릭스·띠타겟·시의성처방 포맷은 few-shots-structure.md, 그 포맷 쓸 때만)
3. `references/banned.md` 는 **읽지 않는다** — 검사는 스크립트로 (아래 자체 검사 참조)
4. 명리 사실은 `data/reference/seun.md` 를 통째로 읽지 말고 `node scripts/lookup.mjs <지지|일간> <연도>` 로 필요한 줄만
5. `data/drafts.json` · `data/posts.json` 은 통째로 Read 금지 (권한에서 차단됨) —
   `node scripts/drafts.mjs [summary|list|pending|show <id>|grep <말>|posts [top N]]` 로 필요한 것만

**few-shots 가 규칙보다 우선한다.** 규칙과 예시가 충돌하면 예시를 따른다.
규칙은 예시에서 못 읽히는 부분만 보조한다.

## voice-profile.md 가 비어 있으면

글을 쓰지 마라. 아래를 출력하고 멈춘다:

> voice-profile 이 비어 있음. 터진 글 최소 20개 + 안 터진 글 10개 붙여넣고 `/voice-extract` 실행해라.

## 초안 작성 절차

1. few-shots 중 이번 소재와 **구조가 가장 가까운 3개**를 먼저 고른다. 어떤 걸 골랐는지 밝힌다.
2. 그 구조를 골격으로 쓴다. 문장은 새로 쓰되 리듬은 복제한다.
   **단, 시그니처 토큰("특징 ; ~ 등등", "~특:", "= XX 사주" 같은 그 글 고유의 표식)은 복제 금지.**
   골격 복제와 지문 복제를 구분하라 — 지문까지 베끼면 원본과 쌍둥이로 보여서 바로 걸린다 (블라인드 1차에서 실증).
3. 아이디어당 3안. 3안은 서로 **앵글이 달라야** 한다. 같은 말 세 번 바꿔쓰기 금지.
4. 각 안마다 첫 문장(훅) 유형을 표기한다.

## 자체 검사 (출력 전 무조건)

- [ ] **300~450자** (실측 WIN 평균 369 / LOSS 170). 상한 500자
- [ ] **한 줄 24자 이하** — 분기 해설(`: ~`) 줄만 예외.
      마침표로 두 문장을 한 줄에 붙였으면 거기서 줄을 나눈다.
      `node scripts/check-lines.mjs "<본문>"` 로 검사. 코퍼스 중앙 17자 / 내 버릇 23자
- [ ] **답글을 뭉치지 않았는가** — 항목이 여럿이면 항목당 한 장(`pages` 배열 원소)으로 쪼갠다.
      한 장 38~140자. 링크는 마지막 장에만. (2026-09-01 지시)
- [ ] **목록형은 문장으로 풀지 않는다** — `이름 : 한 줄` 형태로 붙인다. (2026-09-01 지시)
      나쁜 예: `천복은 록 그 자체임 / 그래서 제일 또렷한 대신 / 자리가 없으면 안 돎` (3줄 문장)
      좋은 예: `천복 : 록 그 자체. 자리를 놓으면 같이 끊김` (1줄)
      항목을 설명하려고 문장을 늘어놓으면 그 자체가 AI 티다. 한정 조항이 있는 마지막 장만 문장체 허용.
- [ ] **독자 분기가 있는가** — 일간·일지·오행·십신 중 하나로 갈래를 치고 각 갈래에 `: 해설`.
      WIN 6.4줄 / LOSS 0줄. 없으면 그 초안은 폐기 (voice-profile 규칙 1)
- [ ] **첫 줄이 13자 이상인가** — 절단 조각 훅(`헤어지고 나서` 류)은 LOSS 50% / WIN 10%. 있으면 폐기
- [ ] **인접 줄 중복 검사** — 공백·조사 제거 후 이웃한 두 줄이 같거나 한쪽이 다른 쪽을 포함하면 폐기.
      (2026-08-27 lr-106: 재작성 때 새 1행이 원문 2행과 같은 문장이라 중복된 채 발행됨.
       Threads 는 수정 API 가 없어 되돌리지 못했다. 기존 글을 고쳐 쓸 때 특히 잘 난다)
- [ ] **마무리가 만세력·전체사주 안내인가** — WIN 70% / LOSS 0%
- [ ] banned.md 단어 0개 — `node -e` 로 banned.md 를 읽어 includes 검사 (파일을 컨텍스트에 올리지 말 것)
      가격·프로모션(990원·할인·무료 등)은 `check-draft.mjs` 가 별도로 잡는다
- [ ] 종결어미 비율이 voice-profile 분포 안에 있는가
- [ ] 문장 길이 분포가 few-shots 와 비슷한가 (긴 문장만 늘어놓지 않았는가)
- [ ] 줄바꿈 리듬이 few-shots 와 같은가
- [ ] 숫자·고유명사가 들어갔는가 (구체성 없는 일반론은 폐기)
- [ ] 첫 문장만 읽고 다음 줄이 궁금한가
- [ ] **"A가 아니라 B" 구문 전수 검사** — "아니라/아니고/아님" 뒤에 재정의가 오는 문장을 전부 찾아서
      마무리·핵심 문장에 있으면 폐기. (블라인드 1차: 생성 5건 중 4건이 이걸 씀. 습관성 결함이니 셀프 신뢰 금지)
      통념반박 훅에서의 사용만 예외 (코퍼스 문법: "~한 살이 아님. ~한 살임.")
- [ ] **대칭 정의 커플릿 검사** — "X는 ~이고 Y는 ~임" 식으로 두 개념을 나란히 정의한 문장 쌍이 있으면
      하나를 비대칭으로 부수거나 합친다. 대구 금지의 변장 형태다 (블라인드 2차에서 걸림)
- [ ] **펀치라인 밀도** — 웃기거나 찌르는 줄이 글당 1개를 넘으면 초과분을 건조한 사실로 강등.
      코퍼스 실제 글은 펀치라인 0~1개, 나머지 줄은 정보만 나른다 (블라인드 2차: 전 줄 펀치 글이 바로 걸림)
- [ ] **명리 사실 검사 — 기계로 돌린다.** `node scripts/check-draft.mjs "<본문>"` 실행하고 결과를 출력에 붙인다.
      FAIL 이 하나라도 있으면 그 안은 폐기. WARN(한정 조항 없음)은 한 줄 추가해서 해결.
      연도·간지·합충원진·삼합·십신·시간대·금지화법·**시점(올해/내년 + 지지 관계)** 을 참조표와 대조한다.
      해석의 타당성은 기계가 못 잡으니 `data/reference/claims.md` 의 3·4번(유파 갈림·금지)을 눈으로 확인.
      (2026-08-26: "내년 자축합" 오류로 댓글 지적 — 자축합은 실재하지만 축은 2033년. 기억으로 쓴 간지는 신뢰 금지)
- [ ] 마지막 문장이 명언처럼 읽히는가 → 읽히면 폐기. 종결은 CTA / 절단 / 무뚝뚝한 사실 / "등등" 여운 4종만

하나라도 실패하면 출력하지 말고 다시 쓴다.

## AI 티 제거 — 사주 청중은 "강의체"에서 바로 이탈한다

- 대구 구조 금지 ("A가 아니라 B다" 반복)
- **요약용** 3단 리스트 마무리 금지 (리스트가 본문 자체인 건 코퍼스 문법이라 허용)
- 헤지 금지 — 본문은 확정 화법, 한정 조항은 마지막 1곳만 (voice-profile 규칙 9)
- **레지스터는 압축체(~함/~임/~됨/명사종결) 고정.** 존대체·반말 구어 금지.
  few-shots 2부(구조 레퍼런스)에서는 골격만 가져오고 문체는 이식하지 않는다.
- 이모지로 문단 시작 금지 (few-shots 에 그런 게 있으면 예외)
- 마무리 질문 CTA는 voice-profile 이 허용한 비율만큼만
- 교훈으로 끝내는 문장 금지. 사실로 끝내라
