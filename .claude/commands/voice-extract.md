# /voice-extract

## 입력 확인

사용자가 글을 붙여넣었는지 확인한다. 없으면 요구하고 멈춘다:

> 터진 글 20개 이상 + **안 터진 글 10개 이상**. 각 글에 조회수 붙여서.
> 안 터진 글이 없으면 대조가 안 돼서 "평균적인 나"만 복제된다.

`data/posts.json` 이 있으면 거기서 읽는다 (`npm run sync` 후).

## 1단계 — 분류

조회수 기준 정렬 → 상위 20% = WIN, 하위 20% = LOSS, 나머지 = MID.
개수와 조회수 중앙값을 표로 보고한다. 표본이 30개 미만이면 그렇게 말한다.

## 2단계 — 측정 (인상이 아니라 카운트)

WIN / LOSS 각각에 대해 **세어서** 수치로 낸다. "친근한 톤" 같은 서술 금지.

- 종결어미: ~함 / ~해요 / ~다 / 명사종결 각 비율
- 평균 문장 수, 평균 문장 길이, 최장/최단
- 줄바꿈: 몇 문장마다 개행하는가
- 이모지: 글당 개수, 위치(첫줄/끝줄/본문)
- 숫자 포함 비율, 고유명사(도구명·서비스명) 글당 개수
- 글 길이 (자수) 분포
- 첫 문장 유형 분류 후 각 유형의 WIN 비율:
  실패담 / 수치제시 / 통념반박 / 질문 / 선언 / 상황묘사
- 마지막 문장 유형: 질문CTA / 사실종결 / 교훈 / 여운
- 1인칭 등장 빈도, 독자 호칭 사용 여부

## 3단계 — 차이 뽑기

WIN 과 LOSS 를 나란히 놓고 **통계적으로 갈리는 항목만** 남긴다.
차이 없는 항목은 규칙에 넣지 마라. 규칙이 많을수록 생성 품질이 떨어진다.
최대 12개 규칙. 넘으면 성과 차이 큰 순으로 잘라낸다.

각 규칙은 이 형식:
`[항목] WIN=<수치> / LOSS=<수치> → 규칙 문장`

## 4단계 — 파일 쓰기

**`references/voice-profile.md`**
STATUS 줄 삭제하고 섹션별로 위 수치 + 규칙 기입. 마지막에 표본 크기와 추출 날짜.

**`references/few-shots.md`**
WIN 중 구조가 서로 다른 8~12개 선별. **원문 그대로. 오탈자·줄바꿈까지 그대로.**
각 글 위 3줄 메타만:
```
<!-- views: 00000 / 훅: 실패담 / 구조: 삽질→원인→배운것 -->
```
정제하거나 다듬으면 이 작업 전체가 무의미해진다.

**`references/banned.md`**
사용자 말뭉치 전체에서 등장 0회인데 LLM이 흔히 쓰는 표현을 30개까지 추가.

## 5단계 — 블라인드 테스트 제안

추출 직후 검증 제안:
> 지금 규칙으로 5개 생성할 테니, 네 실제 글 5개랑 섞어서 구분해봐라.
> 3개 이상 맞히면 규칙 부족이니 표본 늘려야 한다.

## --update 모드

기존 voice-profile 을 읽고 **덮어쓰지 말고 diff 로 보고**한 뒤 승인받고 반영한다.
변한 항목만 갱신. 안 변한 규칙은 건드리지 않는다.
