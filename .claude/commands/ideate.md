# /ideate

## 입력
- `data/posts.json` — 내 글 + 성과
- `data/sources.md` — 소재 (커밋 로그, 외주 작업, 읽은 것, 삽질 기록)
- `references/few-shots.md` — 성공 구조

sources.md 가 비어 있으면 채우라고 요구하고 멈춘다. 소재 없이 아이디어를 지어내지 마라.
**지어낸 경험담은 즉시 들킨다. 실제로 겪은 것만 쓴다.**

## 절차

1. WIN 글에서 **내용이 아니라 구조(앵글)만** 추출해 템플릿화한다.
   예: `삽질 → 원인 → 배운 것`, `통념 → 반박 → 조건`, `수치 → 맥락 → 함의`
2. sources.md 의 각 소재를 어느 템플릿에 얹을지 매핑한다.
   한 소재가 여러 템플릿에 맞으면 각각 별개 아이디어로 만든다.
3. 중복 제거: 기존 글과 주제·앵글이 겹치면 드롭.
   판단 근거를 한 줄로 남긴다 (임베딩 도입 전까지는 수동 판단).
4. 아이디어당 예상 훅 첫 문장을 1개 써본다. 이게 안 나오면 그 아이디어는 약한 거다. 버려라.

## 출력 → `data/ideas.json`

```json
[{
  "id": "idea-001",
  "source": "PORTER 타오바오 이미지 파싱 3일 삽질",
  "template": "삽질→원인→배운것",
  "hook": "<첫 문장 초안>",
  "why_now": "<지금 쓸 이유. 없으면 우선순위 낮음>",
  "score": 0
}]
```

score 는 매기지 말고 0으로 둔다. 사람이 매긴다.
10개 넘게 만들지 마라. 양이 아니라 훅 강도가 병목이다.
